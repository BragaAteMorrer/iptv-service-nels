# Audit initial NSatellite — 9 novembre 2026

## Portée vérifiée

`fix/browser-session-outage-and-ci`. Analyse du code Symfony, interfaces
HTML/JS, routes Apache o2switch, migrations, tests et documentation. Les
résultats ne constituent **pas** une recette de production : aucune session
authentifiée, source IPTV réelle ou configuration privée du serveur n'a
été inspectée.

- PR ouvertes au démarrage : **0**.
- Aucune définition `.github/workflows` présente avant ce lot.
- Déploiement o2switch **manuel** : `deploy/o2switch/install-viewer.sh`
  installe les pages et la passerelle explicitement, après opt-in, depuis
  une copie locale à jour de `main`.
- Pages PC/TV présentes : `home`, `tv`, `catalog`, `series`,
  `lineup`, `devices`; thèmes et guide EPG existants.
- Base cible o2switch : MariaDB ; schéma spécifique dans
  `migrations/mariadb/` ; migrations PostgreSQL conservées pour d'autres
  environnements. Une partie de la documentation historique décrit
  encore une architecture PostgreSQL : ne pas l'appliquer aveuglément.
- Séparation utilisateurs/sources au niveau de `user_source_access` et
  de contrôleurs (à continuer de tester).
- Connexions navigateur par cookie `HttpOnly/Secure/SameSite=Lax`, 7

- Streaming en production : **uniquement HLS direct HTTPS** depuis des
  domaines explicitement approuvés et compatibles CORS. Pas de proxy
  PHP général, ni de garantie de compatibilité Xtream/MPEG-TS.

## Défaut concret corrigé dans ce lot

`public/assets/nsatellite-auth.js` interprétait **toute** erreur du
contrôle de session (HTTP 500, 503, réseau inaccessible, réponse
malformée) comme une session terminée. À l'écran, cela donnait une
**fausse déconnexion** lors d'un incident temporaire sur o2switch.
Désormais : HTTP 401 signifie déconnecté ; toute autre erreur est
signalée. Les pages gèrent cette erreur sans affirmer que le compte
s'est déconnecté.

## Autres limites identifiées (non corrigées dans ce lot)

1. `public/tv.html` charge au maximum 10 pages de 100 chaînes ; les
   chaînes au-delà ne sont pas recherchables dans ce cache local.
   Priorité prochaine : pagination/recherche serveur et décodeur virtuel.
2. Certains liens et fonctions VOD dépendent encore de routes que la
   passerelle de production n'expose pas ; les afficher comme
   indisponibles plutôt que de promettre une lecture universelle.
3. Les tests de sécurité existants sont principalement des scripts
   « smoke » isolés ; il manque une vraie suite navigateur PC E2E et
   une simulation de lecture HLS avec serveur/flux de test maîtrisé.
4. Aucun `composer.lock` dans `main` à la date de l'audit :
   la résolution des dépendances n'est pas figée. Générer et committer
   un verrou testé dans un lot dédié.
5. Un tableau de bord administrateur pleinement utilisable en
   production nécessite une politique de rôles, une passerelle
   dédiée et des permissions ; ne pas publier `admin.html` par
   simple copie du répertoire `public/`.
6. La sécurité et l'expérience du lecteur sur le vrai vhost o2switch
   (certificat, variables privées, droits de sources, codecs, CORS,
   quotas) restent à tester avec l'exploitant.

## Déploiement et retour arrière

Pas de déploiement automatique. Après fusion et validation des checks,
mettre à jour `~/nsatellite` sur o2switch avec `git pull --ff-only`
(sans écraser les changements locaux), vérifier les scripts et
réinstaller les fichiers du portail avec
`NSATELLITE_INSTALL_VIEWER_UI=1 bash deploy/o2switch/install-viewer.sh`.
Le script sauvegarde les fichiers écrasés sous
`var/deploy-backups/browser-...`. En cas de régression, restaurer
la sauvegarde des fichiers servis et la version précédente du code.
Ne pas modifier le schéma SQL pour ce lot.
